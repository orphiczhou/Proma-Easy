## 二、部署工艺记录（含一个重要工艺坑与修复）

部署采用「asar 增量替换」（源码 build → 替换 asar 内 `/dist` + package.json 版本 → 保留 unpacked 原生模块），未走 electron-builder 全量打包。

**⚠️ 工艺坑 D-1（已解决，强烈建议固化为部署 SOP）**：手工重打包 asar 会丢失 `asarUnpack` 语义——首版部署后主进程 `sharp` 模块 `ERR_DLOPEN_FAILED`（libvips `.so` 被打回 asar 内，Electron 不再重定向到 `app.asar.unpacked/`），且早期 uncaught exception 中断了后续初始化（bridge 未监听）。修复：`@electron/asar pack` 必须带
`--unpack-dir "node_modules/{sharp,@img,@napi-rs,@earendil-works,@mariozechner,@silvia-odwyer,jszip}"`
（与 electron-builder.yml 的 `asarUnpack` 清单一致；多个 `--unpack-dir` 参数只有最后一个生效，必须单参数 brace 形式）。修复后实例完全正常。**建议**：把该清单与打包命令写进部署脚本，避免下次部署重复踩坑；或提供 `scripts/deploy-dev-asar.ts` 官方化。

备份留存：`app.asar.bak-pre-v0.17.135-20261103-2337`、`app.asar.unpacked.bak-pre-v0.17.135-*`（可秒级回滚）。
