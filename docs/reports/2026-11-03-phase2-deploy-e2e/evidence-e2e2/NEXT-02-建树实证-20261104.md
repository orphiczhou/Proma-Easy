## 发现的缺口 F-5（已修复，v0.17.136）

**现象**：建树成功后，root 指挥官调用树工具被路由门禁拒绝：

```
[南大路由门禁] 拒绝工具 mcp__tree__tree_leaf_list_active
```

**根因**：`nanju-router-gate.ts` 的 `ACTIVE_PHASE_TOOLS` 未包含 `mcp__tree__*` 与
`mcp__session__send_message` 等会话协调工具；而 `nanju-coding-tree-bridge.buildCommanderPrompt`
的启动契约明确要求 root 指挥官调用 `tree_milestone_add` / `tree_event_append` / `tree_audit_gate` /
`tree_log_communication` 以及 `session_send_message`。→ 树建好却无法驱动，NEXT-02 运行时闭环断裂。
（同一根因也解释了上一轮 HANDOFF「新会话乱调 tree_init 被拒」的观感。）

**修复**（最小放行面）：
- 新增 `TREE_ORCHESTRATION_STAGES = {coding, testing}` 与 `TREE_ORCHESTRATION_SESSION_TOOLS`
  （send_message/list_messages/get_session_info/get_my_session_id）；
- `isTreeOrchestrationToolAllowed()`：该两阶段放行 `mcp__tree__*` 前缀全族 + 上述会话工具；
- 其余阶段（requirements/prototype/architecture/planning）维持原拒绝。
- 单测 5 条（`nanju-router-gate.test.ts` 末段）：coding 放行 tree 族/会话通道、testing 放行、
  prototype 拒绝、放行后 Write 仍 deny。
- 门禁：`bun run typecheck` 全绿；`bun run test` 2837 pass / 0 fail（174 files）。
