## 附带纠正（上一轮 HANDOFF §三 方法教训 1 的误判）

上一轮结论「不能靠改注册表 sessionId 复制调度员会话」不成立。真实原因有两条：

1. **F-1**：注入链路在 `assertACFamilyDiversity` 抛错 → 会话拿不到 router prompt → LLM 裸奔乱调工具被 W19 拦（表象为「接管失败」）。
2. **workspace 未绑定**：bridge `create_session` 不传 `workspace_id` 时 `workspace=null` → orchestrator 的
   `nanjuRouterPrompt = workspaceSlug && ... ? getNanjuRouterPrompt(...) : undefined` 直接跳过注入，
   且 `PHASE_ADVANCE` 消费条件 `msg.type==='result' && workspaceSlug` 也不成立（标记输出 3 次零消费）。

正确姿势：`create_session` 必须带 `workspace_id=16171483-8f38-465e-8ff5-94a400b36562`（slug workspace-1786847832507），
再把注册表 `_nanju-projects.json` 与工程 `_project-info.json` 的 `sessionId` 同步到新会话。
