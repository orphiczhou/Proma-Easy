### 二、平台改进建议（按优先级，均给可执行机制）

**P0-A 把「猜谜关」改成「对账关」——`advance.auto-gate` 必须自述校验契约**

- 失败时透传结构化拒因：`{gate:"advance.auto-gate", validator:"parseEnvChecklistFromDoc", stage:"architecture", checks:[{id, expected, actual, evidencePath, hint}]}`。以本轮为例，正确输出应是：「表格首列 token `[tkinter, xprop, fcntl, X 扩展, wmctrl]` 不在 desktop-app 白名单 `[python3,pynput,xclip,xdotool,node,rustc,cargo,…]`；建议移出表格或改用列表」——一次即可收敛。
- 连续第 2 次同因失败（如 `reject-escalate.count>=2`）时，向调度员开放只读自述通道（`nanju_explain_gate` 或直接在 reject 事件里带 `hint`），避免出现本轮「调度员去读 `proma-easy/dev/` 源码、委派审计从 app.asar 提取验证逻辑」的场面。
- 为判据留版本指纹：本轮同一产物在同一天内被同一门禁以 4 种不同理由拒绝（措辞 / PENDING / URL / 白名单），事后无法判断门禁实现是否期间变更。

**P0-B 关键词门禁：修正误拦 + 关闭「暗语化」旁路**

- 误拦修正（本轮实例）：① 「引用前序产物名」不应触发他阶段词（「根据 PRD 和原型」命中「原型」；「后续测试用例按 US-xx 编号」命中「测试」——两条都是**必须写**的内容）；② 调度员**自拟 title** 不应与 task 同权重（「开发工程师 — 剪贴板历史编码落地」命中「开发」被拒）；③ deny 回复应给"改写建议"（本轮白名单字段质量很高，只差一句"把『原型』改为『上一阶段可交互产出』"）。建议按 `denialKind` 分类统计误拦率并设阈值告警。
- 关闭暗语旁路（更重要）：平台应**检测并拒绝**含"字间空格标题"或 `+` 拼接路径的任务书（正则如 `"[^"]{2,}"\s*\+\s*"[^"]{2,}"`、中文字符间空格且长度>3 的标题词），并在拒因中说明「不允许以变形文本规避扫描；若确需提及他阶段词，请使用平台提供的替代表述白名单」。理由：① 本轮注入文本已实际被污染（「测 试 架 构」「03_ARCH" + "ITECTURE」），Agent 需解码才能工作；② 「为过扫描而改写文本」一旦成为正式指令，会破坏"产物字面 = 契约字面"的可核性（这正是编排版 D-5 型失真的同类风险）；③ 本轮该约定还被用于 title（规避「开发」），说明它会自然扩散到所有字段。

**P0-C 委派中断/硬超时的细节透传（P0-2 真流程实测未命中）**

- `wait_for_delegations` / 委派结果中至少补：`cancelReason`（区分 `delegation_hard_timeout` / 用户取消 / 平台回收）、`errorCount`、`stderrTail`（截尾 ≤32KB）、`lastToolCall`（工具名+参数摘要）、`artifactsWritten`（本次运行落盘的文件+大小+mtime）。

**P1-A 环境事实：注入源、探测脚本、平台状态三者同源 + 机器指纹**

- 任务书注入事实与 `_project-info.envCheck` 必须来自**同一次探针执行**，携带 `probed_at / probe_cmd / tool_version / script_sha256`；`envCheck[].ok` 要么改名（`resolved`）、要么补 `evidence`（探针输出原文）。

**P1-B 验收证据资产化闸门（禁止只落 `/tmp`）**

**P1-C 目录契约与写保护对齐**

- 可选：`Bash` 的 `bash-project-path` 拦截（本项目 24 次，含只读 `cat`/`grep`；我在本次收割中亦复现 1 次）建议先做**只读命令白名单**（`cat/grep/head/ls/find/file/stat/wc/md5sum` 且无重定向/无 `>>`/无 `tee` 时可放行），因为"看内容"被拦会直接推高观察者与审计者的取证成本。

**P1-D 运行终态与无人值守收口**

- gate-deny 后 N 分钟无应答 → 产生终止事件（`project.awaiting-human` / `project.stalled`）并冻结终态，附带「未完成阶段 + 阻塞原因摘要 + 待办动作」。本轮以 `pendingAdvanceCorrection` 停在文件里、遥测无收尾事件，是观察者与用户共同的信息断点。

**P2-A 模板注入按品类选源**：desktop-app 注入 Tauri 模板（D-9）等于注入 0 引用价值 + 增加「弃用声明」负担；建议按 `projectCategory` 选择模板，或在模板内置「本模板不适用时的最小契约」。

**P2-B 凭证门禁从「有 URL」升级到「可核 URL」**：当前只校验行内 http(s) 字面（5 次 verify-failed 中的一轮就是"file:// 不被接受"），机制上允许"贴一个真 URL 但语义不相关"通过。建议：URL 可达性 + 标题/摘要与被引结论同向 + 强制填「被引句子原文」+ 检索日期由平台记录（本轮"检索日期 2026-09-20"是作者手填）；同时把「角色归因」纳入核查（本轮 `architecture.md:129`「维护者确认」在 #154 可见内容中只见报告人自述）。

**P2-C AC 审计产物入项目**：攻击者/防御者原始 findings 建议落 `03_ARCHITECTURE/ac-r<N>-attack.json` / `-defense.json`（本轮 R1 原始报告在 `/tmp/attacker_findings_raw.json`，项目内只有汇总 JSON）。
