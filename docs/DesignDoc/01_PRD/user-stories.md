## 角色一：零基础用户（10条）

### US-U01 · 选择项目模式

| 属性 | 值 |
| --- | --- |
| **优先级** | P0 |
| **PRD追溯** | §3, §3.1, §3.2 |
| **依赖** | 无 |

> 作为零基础用户， 我希望打开应用后看到两个清晰的选择——"快速做一个工具"和"做一个长期维护的项目"——并且每个选项用我能懂的话解释适合什么场景， 以便我不用纠结技术概念就能决定走哪条路。

**GWT验收场景**：

```gherkin
Scenario: 首次启动看到两道门
  Given 用户首次启动应用
  When 主界面加载完成
  Then 界面中央显示两个同等大小的选择卡片，卡片本身即为点击目标（无独立"选择"按钮）
  And 左侧卡片标题为"快速做一个工具"，副标题包含"适合试试想法、做个小工具、验证一个点子"，附带场景举例"比如：做个读书笔记、订餐统计、个人记账"
  And 右侧卡片标题为"做一个长期维护的项目"，副标题包含"适合想持续更新、不断完善的项目"，附带场景举例"比如：开源工具、团队协作平台、长期维护的社区网站"
  And 鼠标悬停卡片时出现高光效果

Scenario: 选择快消型后进入对应工作区
  Given 用户在模式选择页
  When 用户点击左侧"快速做一个工具"卡片
  Then 界面切换为快消型工作区布局

Scenario: 选择长期迭代型后进入对应工作区
  Given 用户在模式选择页
  When 用户点击右侧"做一个长期维护的项目"卡片
  Then 界面切换为长期迭代型工作区布局

Scenario: 用户试图通过浏览器导航绕过选择（边界）
  Given 用户在模式选择页
  When 用户尝试通过浏览器后退按钮、直接输入URL或刷新页面来绕过选择
  Then 系统始终回到模式选择页
  And 两个选项始终可见且必须选择其一才能进入工作区
```

**INVEST自检**：

| 原则 | 判定 | 说明 |
| --- | --- | --- |
| Independent | ✅ | 不依赖任何其他用户故事，可独立交付 |
| Negotiable | ✅ | 卡片文案和布局可协商调整 |
| Valuable | ✅ | 用户明确知道自己在做什么样的项目 |
| Estimable | ✅ | 一个选择页面的UI实现 |
| Small | ✅ | 仅涉及模式选择入口 |
| Testable | ✅ | 4个GWT场景覆盖正常路径和边界 |

### US-U02 · 快消型需求沟通

| 属性 | 值 |
| --- | --- |
| **优先级** | P0 |
| **PRD追溯** | §3.1, §6.1, §7.6 |
| **依赖** | US-U01（模式已选择） |

> 作为零基础用户（快消型模式）， 我希望像跟朋友聊天一样说出我想做什么，向导Agent能不断问我引导性的问题来帮我理清思路， 以便我模糊的想法最终变成一个清晰、可执行的需求方案。

**GWT验收场景**：

```gherkin
Scenario: 从一句话启动需求挖掘
  Given 用户在快消型工作区
  When 用户输入"我想做个记录读书笔记的东西"
  Then 向导Agent不立即生成代码
  And 向导Agent在3秒内回复第一轮引导问题
  And 第一轮问题不少于3个，上限根据需求复杂度动态调整（可超5个）
  And 每个问题以生活化语言表达（不含"数据库""前端""后端"等技术术语）
  And 至少一个问题是卡片选择形式（如"你想记录哪些信息？[书名和作者] [阅读进度] [读书笔记和感想] [以上都要]"）
  And 每个卡片组末尾有"你帮我决定"选项

Scenario: 用户选择"你帮我决定"
  Given 向导Agent提出了一轮问题
  When 用户对某个问题选择"你帮我决定"
  Then 向导Agent基于常见实践自动填补该决策
  And 在需求摘要中标注"自动建议"以便用户后续审查
  And 不要求用户对该问题再做决策

Scenario: 需求信息不足时继续追问
  Given 用户回答了一轮问题但信息仍不充分
  When 向导Agent判断关键决策点尚未覆盖（如核心功能清单不足3项）
  Then 继续提出下一轮问题
  And 每轮不少于3个问题
  And 不重复已确认的信息

Scenario: 信息充分后产出需求摘要
  Given 用户完成了多轮对话
  When 向导Agent判断核心功能清单已覆盖、关键决策已确认
  Then 以自然语言生成需求摘要
  And 摘要结构为："我理解你想做的是[项目一句话描述]。具体包括：[功能1]、[功能2]、[功能3]。不包括：[明确不做的事]。"
  And 用户需回复确认（"对"/"差不多"/"还要改"）才能进入下一步

Scenario: 用户主动要求开始开发
  Given 用户在任何对话轮次中
  When 用户表达"先做出来看看""差不多了先开始吧"等终止沟通意图
  Then 向导Agent不再继续追问
  And 将当前已确认的需求整理为摘要
  And 提示"下面我先给你看一个预览效果，确认没问题就开始做"

Scenario: 用户输入极少信息（边界）
  Given 用户在快消型工作区
  When 用户只输入"做个软件"或"帮我做个东西"等极模糊表述
  Then 向导Agent不报错、不要求用户说得更专业
  And 回复："好的！能多说一点吗？比如这个软件是做什么用的？"并附带几个常见方向卡片（"记录东西""展示信息""和钱有关""和人打交道"）供用户选择

Scenario: 用户连续多轮输入极模糊表述（循环退出）
  Given 用户已连续3轮输入极模糊或重复的表述
  When 用户第4轮仍然只输入"帮我做个东西"等无法进一步明确的内容
  Then 向导Agent不再继续追问
  And 回复："好的，我先根据你目前说的做一个通用版本，后面再根据你的反馈调整。如果有什么特别想要的功能，随时告诉我。"
  And 基于常见实践自动生成一份基础方案并直接进入原型预览

Scenario: 用户在PRD阶段补充验收场景
  Given 需求沟通已进入PRD草案阶段
  When 用户用自然语言表达对某个功能的验收期望（如"我想确认一下如果书名是空的，会不会有提示"）
  Then 向导Agent将该期望转换为GWT场景骨架
  And 回复："明白了，我把它加入测试清单：[场景描述]。交付前我们会确保这一条通过。"
  And 用户补充的GWT场景与系统自动生成的场景统一编号管理
```

### US-U03 · 长期迭代型需求沟通

| 属性 | 值 |
| --- | --- |
| **优先级** | P0 |
| **PRD追溯** | §3.2, §6.2 |
| **依赖** | US-U01（模式已选择） |

> 作为零基础用户（长期迭代型模式）， 我希望向导Agent能更深入地帮我思考项目——不仅是功能，还有使用场景、未来扩展——用我能懂的方式引导我做出更完整的需求规划， 以便项目从一开始就有扎实的基础。

**GWT验收场景**：

```gherkin
Scenario: 首次对话建立项目背景
  Given 用户在长期迭代型工作区
  When 用户描述项目想法
  Then 向导Agent的对话覆盖以下方面（区别于快消型仅关注功能）：
  And ①至少询问1个与使用场景相关的问题（如"这个项目主要是你自己用还是给一群人用？"）
  And ②至少询问1个与未来扩展预期相关的问题（如"你觉得后续可能还想加什么功能？"）
  And ③不设提问轮次硬上限
  And ④至少包含1个追问"为什么"来理解用户需求背后的动机

Scenario: 产出完整PRD需用户逐条确认
  Given 向导Agent已充分收集需求
  When 向导Agent产出完整PRD草案
  Then PRD以自然语言分章节展示
  And 每个章节附带"确认"或"修改"入口
  And 用户逐章确认后PRD标记为"已确认"
  And 用户可要求修改任何章节

Scenario: 用户中途想简化流程（边界）
  Given 用户在长期迭代型需求沟通中
  When 用户表达"不用这么细，先做起来吧"
  Then 向导Agent提示"长期项目建议把基础打好，但如果你确定，我可以简化后面的流程"
  And 用户确认后，后续步骤降为快消型级别（架构师和工程经理隐于后台）
  And 但不改变已确认的PRD内容

Scenario: 用户描述了复杂多模块项目（边界）
  Given 用户在长期迭代型工作区
  When 用户描述的项目涉及多个独立模块（如"既有用户端页面，又有管理后台，还要能导出报表"）
  Then 向导Agent帮助用户梳理模块优先级
  And 引导用户确定第一版的范围（哪些模块先做、哪些后做）
  And 不试图一次沟通覆盖全部模块的细节

Scenario: 用户对PRD草案全盘否定（边界）
  Given 向导Agent已产出PRD草案
  When 用户对所有章节表示"都不对"或"重新来"
  Then 向导Agent不直接抛弃已有内容
  And 引导用户指出最核心的分歧点："我们从头梳理——你觉得最不对的地方是哪里？是整体方向错了，还是具体功能安排不对？"
  And 基于用户的反馈重新从需求挖掘阶段开始
```

### US-U04 · 预览HTML原型

| 属性 | 值 |
| --- | --- |
| **优先级** | P0 |
| **PRD追溯** | §7.2 |
| **依赖** | US-U02 或 US-U03（PRD已确认） |

> 作为零基础用户， 我希望在正式开始开发之前看到一个可以点、可以看的"预览版"页面， 以便我直观地判断做出来的东西是不是我想要的，而不是靠看文字描述来想象。

**GWT验收场景**：

```gherkin
Scenario: PRD确认后自动展示原型
  Given 用户已确认PRD
  When 向导Agent完成原型生成（快消型≤30秒，长期迭代型≤60秒）
  Then 工作区右侧预览面板自动展示原型首页
  And 原型包含模拟数据，且满足：①每个PRD功能项在原型中有对应的可交互入口（按钮/链接/表单）；②模拟数据内容是贴合项目场景的具体值（如"读书笔记"项目则出现"百年孤独""精彩的开篇"等，而非"Item 1""示例文本"等占位符）；③原型中不含PRD未提及的功能入口（AI主动建议的标注项除外）
  And 页面中的按钮、链接可点击，产生对应交互（如跳转、弹窗）

Scenario: 原型预览中用户表达修改意见
  Given 用户正在预览原型
  When 用户说"这个按钮不应该在这里"/"我觉得缺了一个搜索框"
  Then 向导Agent确认用户意图后更新原型
  And 预览区刷新展示修改结果
  And 修改前自动创建快照

Scenario: 用户确认原型
  Given 用户正在预览原型
  When 用户表达满意（"可以""挺好""就这样"等）
  Then 向导Agent记录原型确认状态
  And 进入架构设计阶段

Scenario: UI/UX顾问主动补充专业建议（体现专业水平）
  Given 用户已确认的PRD中未包含"登录功能""设置页面"等常见辅助页面
  When 原型生成完毕
  Then 原型中除了PRD明确要求的功能页面外，额外包含UI/UX顾问基于项目类型和行业最佳实践主动建议的页面或组件
  And 每个主动建议项标注"AI建议"标识
  And 以列表或卡片形式向用户呈现："根据你的项目类型，我建议加上以下功能——你觉得哪些需要保留？"
  And 用户可逐项勾选保留或删除（"加减法"模式）
  And 每个主动建议项附带简短的理由说明（如"大多数管理类工具都会有设置页面，方便用户调整偏好"）
  
  批注：感觉这里向导在做 UI 的时候，应该加上客户没有想到、但通常软件产品设计中应该具备的功能。这些功能不应该由客户显性地提出，而应该体现出我们向导的专业水平，以及 UI/UX 设计 Agent 的专业水平。建议尽量完善出来给客户确认，让他去做减法。
```

### US-U05 · 点选纠错

| 属性 | 值 |
| --- | --- |
| **优先级** | P0 |
| **PRD追溯** | §7.3 |
| **依赖** | US-U04（原型已生成） |

> 作为零基础用户， 当我说不清楚"哪里不对"的时候，我希望直接点击预览页面上的那个东西，系统就能理解我要改什么， 以便我不用学任何技术术语就能精确表达修改意图。

**GWT验收场景**：

```gherkin
Scenario: 点击元素后描述修改意图
  Given 用户在预览原型中看到不满意的元素
  When 用户点击该元素（如一个蓝色按钮）
  Then 被点击的元素出现高亮边框（持续3秒）
  And 向导Agent回复："好的，我看到了这个[自动识别元素类型，如'按钮']。你想怎么改？"
  And 附带几个快速选项卡片（如"换个颜色""换个位置""改文字""删掉它""其他"）

Scenario: 快速选项产生修改
  Given 用户点击了元素并看到快速选项
  When 用户选择"换个颜色"再选择"红色"
  Then 编程Agent修改该元素的颜色为红色
  And 预览区在3秒内刷新展示修改结果
  And 系统自动创建修改前快照

Scenario: 用户自然语言描述修改
  Given 用户点击了元素并看到向导Agent的询问
  When 用户不用快速选项而直接输入"把它挪到页面右上角，再小一点"
  Then 向导Agent理解该自然语言修改意图
  And 编程Agent执行修改
  And 预览区刷新展示结果

Scenario: 点击了不可交互的背景区域（边界）
  Given 用户在预览原型中
  When 用户点击了页面空白背景而非可交互元素
  Then 向导Agent回复："这个位置好像没有可以修改的组件。你想在页面上的哪个具体元素？可以试试点按钮、文字或图片。"
  And 不产生错误提示

Scenario: 连续快速点击多个元素（边界）
  Given 用户在预览原型中
  When 用户在2秒内连续点击3个不同元素
  Then 系统以最后一次点击为准
  And 只高亮最后一个元素

Scenario: 用户框选多个元素同时修改
  Given 用户在预览原型中
  When 用户在页面上拖拽框选了一个区域（包含多个相邻元素）
  Then 被框选的元素组出现高亮边框
  And 向导Agent回复："好的，我看到了这几个元素。你想怎么改它们？"
```

```gherkin
  Given 前两次修复均失败
  When 触发第三次自动修复

  And 仍失败则触发熔断

  When 熔断触发
  Then 编程Agent将项目代码回滚到本次任务开始前的快照
```
