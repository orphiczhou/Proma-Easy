# 审计说明书：PlantUML 时序图

> 适用任务：PKG-D3（sequence-diagrams/）
> 审计方法：四维并行审计 + 回归收敛

---

## 一、审计角色定义

### 审查员A：流程覆盖度审计

对照PRD和架构，检查5个时序图是否覆盖所有关键流程：

| 流程 | 来源 | 对应SEQ |
|------|------|---------|
| 项目创建→PRD→原型→架构 | PRD §6.1/6.2, user-flows Flow1/2 | SEQ-1 |
| 角色路由切换 | PRD §4.3, US-G06, B2报告 | SEQ-2 |
| 代码生成+测试 | PRD §6, US-P01/P03 | SEQ-3 |
| 裁判审查判定 | PRD §9, US-J01/J02 | SEQ-4 |
| 异常自愈熔断 | PRD §6.3, US-P02, US-U07 | SEQ-5 |

此外检查：每个SEQ是否覆盖正常路径 + 至少1个异常/边界分支。

输出：`[A] 流程 | PRD出处 | SEQ# | 覆盖状态 | 缺失分支`

**通过标准**：5个核心流程全覆盖，每个含正常+异常路径。

### 审查员B：PlantUML语法与一致性审计

- 每个 `.puml` 文件语法有效
- 参与者名称与 `class-diagram.puml` 完全一致（逐个比对）
- 消息在参与者之间传递，不指向未定义的参与者
- `alt/else/loop` 语法正确
- `note` 不包含面向用户的内容

输出：`[B] 问题 | 文件 | 位置 | 严重度`

**通过标准**：零语法错误，参与者与类图100%一致。

### 审查员C：PRD工作流一致性审计

逐SEQ对照PRD工作流描述：
- SEQ-1 vs PRD §6.1/6.2 快消型/长期迭代型流程
- SEQ-2 vs PRD §4.3 角色切换描述（注意：探索结论改为串行）
- SEQ-3 vs PRD §6.3 编程Agent流程
- SEQ-4 vs PRD §9.2 双重约束描述
- SEQ-5 vs PRD §6.3 异常自愈3次→熔断→回滚

输出：`[C] 差异点 | PRD描述 | SEQ实现 | 判定`

**通过标准**：与PRD工作流零矛盾（注意：SEQ-2的串行实现是探索结论驱动的PRD实现选择，不算矛盾）。

### 审查员D：user-stories GWT场景追踪

检查时序图中的关键消息是否有对应的GWT验收场景：
- SEQ-1中"用户确认PRD"消息 → 对应 US-U02/U03 的确认场景
- SEQ-2中"展示新角色对话风格" → 对应 US-G06 的可观测切换行为
- SEQ-3中"自修复成功/失败" → 对应 US-P02 的修复场景
- SEQ-4中"硬约束退回" → 对应 US-J01 的退回场景
- SEQ-5中"熔断后安抚通知" → 对应 US-U07 的用户感知场景

输出：`[D] 消息 | 对应的GWT场景 | 覆盖状态`

**通过标准**：5个关键消息均有对应GWT场景。

## 二、工作流程

同PKG-D1：四维并行 → 汇总分级 → 修正 → 回归 → 收敛。

### 分级标准
- **阻塞**：核心流程缺失 / 语法不可解析 / 参与者与类图不匹配
- **严重**：缺失异常分支 / 与PRD工作流矛盾 / 关键消息无GWT对应
- **建议**：分支可更详细、note可更清晰

### 收敛判定
- 阻塞+严重 = 0
- 5个SEQ全覆盖核心流程
- 与类图参与者100%一致
- 与PRD工作流零矛盾
