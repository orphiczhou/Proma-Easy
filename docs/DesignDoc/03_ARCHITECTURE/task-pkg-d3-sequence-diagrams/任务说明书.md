## 三、产出内容（5个时序图）

每个时序图产出为一个独立的 `.puml` 文件，放入 `sequence-diagrams/` 目录。

### SEQ-1：用户创建项目全流程

`user-create-project.seq.puml`

覆盖：用户打开应用 → 模式选择 → 需求对话（需求分析师+UI/UX顾问交替）→ PRD确认 → 原型预览 → 架构设计（快消型隐后台 / 长期型跳到前台）

参与者：用户、GuideAgent、RequirementAnalyst、UIUXAdvisor、ArchitectDesigner、EngineeringManager

### SEQ-2：Agent角色切换机制

`agent-role-switch.seq.puml`

覆盖：阶段判定 → 上下文序列化 → Session Restart → 新角色System Prompt加载 → Context Backfill → 对话恢复

参与者：GuideAgent、SessionRouter、各角色类

对应：US-G06 GWT场景、B2报告Session Restart实现

### SEQ-3：编程Agent生成-测试-修复循环

`code-generation-loop.seq.puml`

覆盖：接收文档包 → 读取PlantUML约束 → 代码生成 → 构建错误 → 自修复（最多3次/每次换策略）→ GWT测试执行 → 成功/熔断

参与者：CodingAgent、TestAgent、SandboxManager

对应：PRD §6.3 异常自愈

### SEQ-4：裁判Agent审查判定流程

`judge-review-flow.seq.puml`

覆盖：文档提交 → 硬约束逐项检查 → 退回/通过 → 代码提交 → PlantUML一致性校验 → GWT覆盖检查 → 综合判定

参与者：GuideAgent、JudgeAgent、HardConstraintChecker、SoftConstraintEvaluator

对应：PRD §9 裁判Agent机制

### SEQ-5：异常自愈熔断回滚流程

`auto-healing.seq.puml`

覆盖：代码错误 → 第1次修复（直接修正）→ 第2次修复（重读文档）→ 第3次修复（替换技术方案）→ 熔断 → 快照回滚 → 用户通知 → 快消型编程层闭环 / 长期迭代型出具变更说明

参与者：CodingAgent、SnapshotManager、GuideAgent、用户

对应：PRD §6.3 异常自愈、US-P02、US-U07

## 四、PlantUML规范

- 每个参与者名称必须与 `class-diagram.puml` 中的类名**完全一致**
- 消息箭头区分：同步调用(`->`)、返回(`-->`)、异步(`->>`)
- 使用 `alt/else` 表示分支（如快消型 vs 长期迭代型）
- 使用 `loop` 表示循环（如自修复3次）
- 使用 `note` 标注关键决策点
- 每个文件头部注释含文档ID、版本、依赖
