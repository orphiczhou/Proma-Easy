## 核心问题

编程Agent需要在本地安全地执行代码生成、构建、测试。需要一个隔离的沙箱环境。

## 候选方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **WebContainer** | 浏览器内运行Node.js | 零安装、完全隔离 | 仅支持Node.js生态、内存受限 |
| **Docker** | 容器化隔离 | 完整Linux环境、成熟稳定 | 需要用户安装Docker、启动慢 |
| **iframe + 代码沙箱API** | 浏览器沙箱 | 轻量、零依赖 | 能力受限、不支持服务端运行 |
| **子进程隔离** | Node.js child_process + 资源限制 | 轻量、本地 | 隔离性较弱 |
| **Proma 现有机制** | 探索Proma是否已有沙箱 | 最大复用 | 可能不满足需求 |

## 评估维度

对每种方案评估：

1. **隔离安全性**：用户代码能否访问本地文件系统/网络？
2. **安装门槛**：零基础用户是否需要额外安装软件？
3. **语言/框架支持**：能运行哪些技术栈？（Node.js/Python/前端三件套）
4. **性能**：启动时间、内存占用、执行速度
5. **与Proma集成难度**：改造量
6. **GWT测试支持**：能否运行自动化测试框架（Cucumber/Jest等）？
7. **错误恢复**：沙箱崩溃后能否快速重建？

## 输出要求

产出一份 `sandbox-report.md` 放在本文件夹内，包含：

1. **方案对比矩阵**：上述6个维度的逐项评分
2. **推荐方案**：第一选择 + 备选方案，附理由
3. **集成方案**：推荐方案与 Proma 的具体对接方式
4. **风险清单**：选型的主要风险及缓解措施
5. **验证计划**：如何快速验证推荐方案的可行性（最小可行测试）

## 关键约束

- 零基础用户**不能**被要求安装 Docker 或配置复杂环境
- 编程Agent需要能运行 `npm install`、`node`、`python` 等命令
- GWT测试需要能在沙箱中运行并产出报告
