## 子任务 T1.4：MiniMax 2.7 多模态基础验证

### 测试1：视觉理解——布局审查

**操作**：
1. 在浏览器打开我们的6个HTML原型（`wireframes/index.html` 或逐个打开）
2. 对每个页面截图
3. 将截图发给 MiniMax 2.7

**Prompt 模板**：

```
请审查这个页面截图的UI设计质量，从以下维度给出具体评价和改进建议：

1. 布局合理性：元素排列是否清晰？信息层级是否明确？
2. 对齐一致性：同类元素是否对齐？间距是否均匀？
3. 颜色对比度：文字与背景的对比度是否足够？关键信息是否突出？
4. 交互直观性：按钮和可点击元素是否容易识别？操作流程是否自然？
5. 零基础用户友好度：一个完全不懂电脑的人会觉得这个页面好理解吗？

每个问题请：定位具体位置（如"左上角的按钮"）、描述问题、给出修改建议。
```

### 测试2：视觉差异对比

**操作**：
1. 准备两个版本的同一页面——一个按 design-system 规范，一个故意修改了几个错误（颜色不对、间距错乱、缺元素）
2. 把两张截图一起发给 MiniMax 2.7

**Prompt 模板**：

```
这是同一个页面的两个版本。第二张图（错误版）相比第一张图（正确版）有几个故意为之的UI问题。请找出所有差异，并说明哪个版本更好、为什么。

对于每个差异，描述：位置、差异内容、对用户体验的影响。
```

### 测试3：设计建议生成

**操作**：不提供截图，纯粹测试 MiniMax 的视觉设计知识。

**Prompt 模板**：

```
我需要为一个面向零基础用户的桌面应用设计UI。应用是一个"AI编程助手"，主界面左侧是聊天对话区，右侧是生成的软件预览区。

目标用户：完全不懂编程的普通人（文科生、办公人员）

设计约束：
- 主色 #2E75B6
- 让用户感觉安全、亲切、不害怕
- 零技术术语
- 所有操作都有明确的视觉反馈

请给出：
1. 布局建议（聊天区和预览区的比例、位置关系）
2. 配色方案（主色外的辅色、功能色建议）
3. 3个关键交互的视觉设计建议（如：等待状态、成功状态、异常恢复）
4. 一个你推荐的参考设计风格或产品
```

### 评估维度

| 维度 | 评估标准 |
|------|---------|
| 定位准确性 | 能否精确描述截图中的元素位置和样式？ |
| 问题发现率 | 能否发现我们预设的UI问题？误报率？ |
| 建议可行性 | 修改建议是否具体、可执行？ |
| 上下文理解 | 能否理解零基础用户的特殊需求？ |
| 响应速度 | 图片分析耗时？ |

## 子任务 T3.10：MiniMax 2.7 原型审查端到端验证

### 说明

模拟 UI/UX 顾问角色的实际工作流程——对我们的6个HTML原型进行完整审查，产出结构化的审查报告。

### 任务

**对6个HTML原型页面逐个审查**，每个页面截图后发给 MiniMax 2.7。

**6个页面**：
1. `page-mode-selection.prototype.html` — 两道门选择页
2. `page-quick-workspace.prototype.html` — 快消型工作区
3. `page-long-workspace.prototype.html` — 长期迭代型工作区
4. `page-my-projects.prototype.html` — 我的项目
5. `page-settings.prototype.html` — 设置页
6. `page-analytics-dashboard.prototype.html` — 分析看板

**但不要只说"6个都审一遍"**。你需要针对每个页面的定位，设计不同的审查重点：

| 页面 | 审查重点 |
|------|---------|
| 模式选择页 | 两道门是否等权、引导文案是否易懂、视觉吸引力 |
| 快消型工作区 | 聊天+预览双区布局比例、需求沟通流程的自然感 |
| 长期迭代型工作区 | 聊天+文档面板+预览三区布局、信息密度是否过高 |
| 我的项目 | 列表扫描效率、项目状态一目了然度 |
| 设置页 | 选项分组清晰度、默认值合理性 |
| 分析看板 | 图表可读性、数据筛选易用性 |

### 完整审查 Prompt 模板

```
你是一个UI/UX审查专家。请审查这个页面截图，这是面向零基础用户的AI编程助手应用中的一个页面。

页面名称：[页面名称]
页面功能：[一句话功能描述]
目标用户：完全不懂编程的普通人

请从以下维度审查，每个问题给出：问题定位、严重程度（阻塞/严重/建议）、具体修改方案。

1. 视觉层级：最重要的信息是否最先被看到？视线流动是否自然？
2. 交互清晰度：用户是否一眼就知道能做什么、该点哪里？
3. 文案质量：所有文字零基础用户都能理解吗？有无技术术语？
4. 设计系统一致性：颜色、字体、间距是否与全局规范一致？
   （参考主色 #2E75B6，字体系统默认栈，卡片圆角 12px）
5. 安全感设计：按钮位置是否防误触？有没有让用户焦虑的设计？
6. 响应式/窗口适配：窗口缩小时布局是否仍然可用？

输出格式：
| # | 位置 | 维度 | 严重度 | 问题描述 | 修改建议 |
|---|------|------|--------|---------|---------|
| 1 | 右上角按钮 | 交互清晰度 | 严重 | 按钮文字"..."零基础用户不理解 | 改为"..." |

最后总结：这个页面最大的3个优点和3个需要改进的地方。
```

### 评估维度（对 MiniMax 审查结果的质量评估）

| 维度 | 说明 |
|------|------|
| 问题发现数量 | 相比我们已知的问题，发现率？ |
| 问题分级准确度 | 阻塞/严重/建议的分级是否合理？ |
| 修改建议可执行性 | 建议是否足够具体，开发可直接采纳？ |
| 零基础视角 | 是否真正从零基础用户角度发现问题（而非专业UI角度）？ |
| 与 gemini-3.1-pro 对比 | （如果通道A已测过gemini）MiniMax的审查质量与gemini差异？ |

3. **MiniMax 2.7 能力总结**：
   - 视觉理解准确率评价
   - 设计建议质量评价

4. **使用建议**：
   - 最佳的截图分辨率和格式
   - Prompt 技巧（MiniMax 对什么类型的指令响应最好？）
   - 与 gemini-3.1-pro 的差异定位（如果已测gemini）
