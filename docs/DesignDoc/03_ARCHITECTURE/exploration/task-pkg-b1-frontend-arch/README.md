# 任务包 B1：Proma 前端架构与扩展点分析

> 通道：B（Pro会话） | 依赖：无 | 预计耗时：1-2小时

---

## 任务目标

深入分析 Proma 的前端架构，明确我们新增的6个页面如何挂载到现有体系中。

## 核心问题

1. **UI框架**：Proma 前端用的什么框架？（React/Vue/Electron/其他？）技术栈是什么？
2. **组件树**：核心组件层级是什么？App → Layout → Page 的嵌套结构是怎样的？
3. **路由机制**：页面路由如何定义？新增一个页面需要改哪些文件？
4. **工作区布局**：Proma 现有的聊天面板/侧边栏/主区域布局是怎么实现的？我们的"聊天+预览"双区布局能否复用现有Layout组件？
5. **扩展点**：Proma 是否有插件/扩展机制？新增页面和功能模块的标准方式是什么？
6. **样式体系**：Proma 现有的CSS/样式方案是什么？我们的 design-system 如何对接？

## 输出要求

产出一份 `frontend-arch-report.md` 放在本文件夹内，包含：

1. **技术栈清单**：框架、构建工具、状态管理、UI库
2. **组件架构图**：用 Mermaid 或文本树画出核心组件层级
3. **路由表**：现有路由列表 + 标注新页面插入点
4. **挂载方案**：我们的6个页面（模式选择/快消型工作区/长期型工作区/我的项目/设置/分析看板）各自怎么接入
5. **改动量预估**：新增文件数、修改文件数、代码量级估算
6. **风险点**：接入过程中可能遇到的兼容性问题或架构冲突

## 方法建议

1. 先读 `package.json`、构建配置文件了解技术栈
2. 读入口文件找到路由定义和组件挂载点
3. 用 SubAgent 并行搜索关键模式（如 `Router`、`Route`、`Layout`、`Page`、`plugin`、`extension`）
4. 对照我们的 sitemap 和 wireframes，逐一匹配挂载方案
