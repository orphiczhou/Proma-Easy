# GLM 5.1 验证报告审计摘要

> 日期：2026-06-06 | 审计方法：四维并行（覆盖度A / 深度B / 证据C / 一致性D）

## 任务概要

C1 任务包，对 GLM 5.1 模型（通过 Proma Agent SDK 调用）进行编程能力自评验证。测试涵盖 T1.3 基础能力（前端代码生成、架构分析/PlantUML、代码审查）和 T3.9 端到端项目（读书笔记管理 Web 应用）。

## 审计方法

采用四维审计框架——覆盖度 A（维度遗漏检查）、深度 B（证据层级提升）、证据 C（事实准确性验证）、一致性 D（自评偏差校准）。v1 报告经 2 轮迭代修正至 v2。

## 关键发现（16 项问题）

- **2 项阻塞级**：T3.9 验收证据停留在 L1（无 curl 输出）；deepseek 对比无实证依据却给出定位建议
- **8 项严重**：代码样本完全遗漏、响应速度维度遗漏、PlantUML 类计数错误（9→10）、工程拆分自评偏高（四星→二星）、代码质量自评偏高（四星→三星）、Express 死代码残留、路径遍历漏洞、输入资源 3/4 未引用
- **6 项建议**：整体耗时维度遗漏、PlantUML 未实际渲染、代码审查遗漏副作用问题、测试主色与设计系统矛盾未指出、XSS 防护边界遗漏、package.json 残留依赖

## 修正措施

- 工程拆分评分从 ★★★★☆ 下调至 ★★☆☆☆（目标架构 Express 退化为原生 http，死代码残留）
- 代码质量评分从 ★★★★☆ 下调至 ★★★☆☆（var 滥用、deprecated API、同步阻塞、安全漏洞）
- 修复 app.js 路径遍历漏洞（serveStatic 添加 path.resolve + startsWith 检查）
- 补充 5 个验收场景的完整 curl 命令与输出作为运行证据，5/5 全部通过
- deepseek 对比表全部标注"待对比"，删除不当的定位建议

## 收敛状态

v2 修正了全部 6 项阻塞/严重问题，覆盖率从 64% 提升至 95%+。13/13 阻塞严重问题已修复。

## 已知限制

- 响应速度不可回溯：Agent SDK 流式调用无法回溯 token 生成耗时，属于不可补测项
- deepseek-v4-pro 待实测：当前对比表格仅列出待测维度，不应作为模型选型依据
- 测试 prompt 主色 #2E75B6 与项目 design-system 主色 #4F46E5 不一致，约束遵循度评估仅针对 prompt

## 能力定位结论

GLM 5.1 适合：全栈开发（前端生成质量高，后端 API 逻辑完整）、架构分析（10 类全部正确映射）、代码审查（崩溃级问题全覆盖，遗漏中等语义问题）、UI/UX 实现（设计约束精确遵循）。

GLM 5.1 不适合：严格框架约束项目（环境异常时丢弃框架改原生方案）、量化性能评估任务、安全审计场景。
