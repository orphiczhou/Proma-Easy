深入分析 Proma 的会话管理和上下文持久化机制，验证我们的向导Agent角色路由和跨阶段上下文保持方案是否可行。

## 核心问题

1. **对话状态管理**：Proma 如何管理单次对话的状态？消息历史存储在哪（内存/文件/数据库）？
2. **System Prompt 加载**：当前的 System Prompt 是怎么加载的？能否支持运行时动态切换？（我们的需求：需求分析师↔UI/UX顾问↔架构设计师↔工程经理四个Prompt按阶段切换）
3. **多模型绑定**：一个会话能否绑定不同模型？切换Prompt时能否同时切换模型？（我们的需求：不同角色绑不同模型）
4. **多Agent并发**：Proma 是否支持同一会话中同时调用多个模型？（我们的需求：需求分析师+UI/UX顾问并行在线）
5. **上下文持久化**：对话历史如何持久化？跨会话恢复的机制是什么？上下文token窗口管理的策略？
6. **会话间通信**：不同会话之间能否共享上下文或传递数据？

## 输出要求

产出一份 `session-context-report.md` 放在本文件夹内，包含：

1. **会话生命周期**：从创建到销毁的完整流程图
2. **System Prompt 机制**：当前实现方式 + 扩展方案（如何支持动态切换）
3. **多模型支持现状**：当前是否支持？如果不支持，改动方案是什么？
4. **上下文管理**：存储方式、持久化策略、跨会话恢复能力
5. **可行性结论**：
   - 角色路由：✅/⚠️/❌ + 需要的改动
   - 多模型并发：✅/⚠️/❌ + 需要的改动
   - 跨阶段上下文保持：✅/⚠️/❌ + 需要的改动
6. **改动量预估**

## 关键约束

我们的需求分析师和UI/UX顾问需要**并行在线**——用户在一轮对话中可以同时获得文字引导和视觉原型反馈。这是架构可行性的关键判定点。
