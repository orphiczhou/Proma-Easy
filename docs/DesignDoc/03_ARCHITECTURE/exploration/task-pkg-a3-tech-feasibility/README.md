## 子任务（4个SubAgent并行）

### A3.1 PlantUML 解析与代码结构对比

**核心问题**：能否用 Node.js 解析 `.puml` 文件 → 提取类/方法/关系 → 与代码实际结构对比？

**调查项**：
1. Node.js 可用的 PlantUML 解析库（npm 搜索）
2. 解析能力：能否提取类名、属性、方法、关系？
3. 代码结构提取工具（如 AST 解析器）：能否提取 TypeScript/JavaScript 的类定义？
4. 两者的对比逻辑复杂度评估

**输出**：技术选型建议 + 集成复杂度 + npm 包清单

### A3.2 GWT 测试框架集成

**核心问题**：在 Node.js 环境中运行 Gherkin/Cucumber 测试的可行方案？

**调查项**：
1. npm 上的 Gherkin/Cucumber 库（@cucumber/cucumber 等）
2. 是否支持在代码中编程式调用（而非 CLI）？
3. Step Definitions 的自动生成可行性？
4. 与编程Agent的代码生成流程如何对接？

**输出**：推荐框架 + 集成方案 + 示例代码结构

### A3.3 轻量级快照与回滚方案

**核心问题**：用户项目的文件级快照和线性回滚的最简可行方案？

**调查项**：
1. 方案A：全量备份（复制整个项目目录）——简单但占空间
2. 方案B：Git 快照（git stash/branch）——轻量但依赖 Git
3. 方案C：文件差异存储（记录变更的文件清单和内容）——最轻量但复杂
4. 每种方案的空间和时间复杂度分析

**输出**：推荐方案 + 存储量级估算 + 集成复杂度

### A3.4 全量埋点采集方案

**核心问题**：13个埋点事件的无侵入采集、本地存储、脱敏方案？

**调查项**：
1. 采集方式：日志文件？SQLite？JSON追加？
2. 13个事件的数据结构设计（JSON Schema）
3. 脱敏策略：正则替换姓名/手机号/邮箱的可行性
4. 对用户体验的性能影响评估（单次埋点写入延迟）
5. 数据保留策略的实现（30天自动清理）

**输出**：推荐方案 + 事件结构定义 + 存储格式
