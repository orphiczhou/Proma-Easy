# A2.2 多模型并发调用可行性验证

> 任务：通道A SubAgent | 日期：2026-06-05 | 状态：已完成

---

## 综合结论

**能不能实现需求分析师+UIUX顾问并行在线？——可以。**

推荐方案：拆为两个逻辑子会话，各绑不同模型，主Agent汇流结果。

## 逐项调查

### 1. Provider 适配器层 — ✅ 可行

`packages/core/src/providers/index.ts` 中维护单例注册表 `Map<ProviderType, ProviderAdapter>`。所有适配器是纯逻辑/无状态的——`buildStreamRequest()` 每次调用产生独立请求配置，不维护任何连接池、锁或互斥变量。

**结论**：适配器层完全支持并发调用，改动量 0。

### 2. sendMessage() 并发守卫 — ⚠️ 有条件可行

`agent-orchestrator.ts` 第509行：`activeSessions = Map<string, number>`，按 sessionId 互斥——同一 sessionId 串行，不同 sessionId **可以并行**。

**方案A（推荐）**：拆为两个逻辑子会话。主Agent创建两个后台会话（不同sessionId），各绑不同模型，通过 EventBus 汇流结果。改动约3-4文件，~80-120行代码。

**方案B（激进）**：移除 session 级 guard 实现真并行。改动约5-6文件，~300行代码，风险更高。

### 3. SDK query() 并发能力 — ✅ 可行

`claude-agent-adapter.ts` 中 `query()` 是 `async *` 生成器，每次调用创建独立的 `AbortController`、独立的子进程。不同 session 的 query 完全隔离，无全局互斥。

**结论**：可以同时调用两次 `adapter.query()`，得两个独立的 `AsyncIterable` 流。改动量 0。

### 4. SubAgent 机制 — ❌ 不可行（作为并行方案）

SubAgent（code-reviewer/explorer/researcher）是 SDK 内建的串行工具——主Agent一次只能委派一个，且 `toolUseConcurrency: 1` 强制顺序执行。

**结论**：SubAgent 适合依次委派场景，不适合两个角色同时在线协作。

### 5. Provider 类型定义 — ✅ 无阻拦

`packages/shared/src/types/agent-provider.ts` 中的 `AgentProviderAdapter` 接口不含并发限制字段。从类型系统角度，多次 `query()` 完全合法。

### 6. Proma Cloud API — ✅ 不涉及

Agent 模型调用不经过 Proma Cloud API，直接由 Provider Adapter 向各模型供应商发请求。不存在 Proma 服务端并发限制。

## 推荐架构

```
向导 Agent（主会话，协调者）
     │
     ├── 后台会话1 → SDK子进程 → 需求分析师（deepseek-v4-flash）
     │        └── 通过 EventBus 返回分析结果
     │
     ├── 后台会话2 → SDK子进程 → UI/UX顾问（MiniMax 2.7/gemini-3.1-pro）
     │        └── 通过 EventBus 返回原型反馈
     │
     └── 汇流结果，整合呈现给用户
```

**这个方案可行因为**：
- Proma 原生支持多 sessionId 并行
- 每个 sessionId 可绑定不同 channel（不同 API Key + 模型）
- 每个 SDK query 是独立 OS 子进程，互不干扰
- EventBus 已支持跨会话事件分发
