# A1.3 Proma Agent 定义与调度机制

> 任务：通道A SubAgent | 日期：2026-06-05 | 状态：已完成 | **版本：v0.2 L3深度修正版**

## 核心发现

### 1. System Prompt 运行时不可切换

System Prompt 在 SDK `query()` 调用时通过两层叠加一次性构建：
- **preset**: `'claude_code'`（SDK内置：platform/shell/OS/git/model信息）
- **append**: `buildSystemPrompt()` 拼接的动态模板（角色定义+工具指南+SubAgent策略+工作区信息+记忆系统+交互规范）

`buildSystemPrompt()` 是纯粹的字符串拼接函数，整个会话周期内不可更改。

**证据**：`agent-orchestrator.ts` L1527-1539：
```typescript
systemPrompt: {
  type: 'preset',
  preset: 'claude_code',
  append: buildSystemPrompt({
    workspaceName: workspace?.name,
    workspaceSlug,
    sessionId,
    permissionMode: initialPermissionMode,
    memoryEnabled: (() => { const mc = getMemoryConfig(); return mc.enabled && !!mc.apiKey })(),
    claudeAvailable,
    deepSeekSubagentModel: modelRouting.subagentModel,
  }),
},
```

`buildSystemPrompt()` 函数定义在 `agent-prompt-builder.ts` L155-474。这是一个纯字符串拼接函数：调用后将所有 sections 拼合返回（L474 `return sections.join('\n\n')`）。System Prompt 在 `sendMessage()` 调用开始时通过 `queryOptions` 即确定（L1508-1539），整个会话周期不可更改。

**如果要支持角色切换，需要在 SDK query() 调用之前确定使用哪套 Prompt。**

### 2. SubAgent 是最佳扩展点

现有的 `buildBuiltinAgents()` 定义了3个内置SubAgent（code-reviewer/explorer/researcher），格式为：

```typescript
{
  description: string,        // 自然语言描述
  tools?: string[],           // 允许的工具
  disallowedTools?: string[], // 禁止的工具
  prompt?: string,            // 自定义提示词
  model?: string,             // 模型
  maxTurns?: number           // 最大轮次
}
```

**证据**：

`SUBAGENT_METADATA` 常量定义于 `agent-prompt-builder.ts` L33-88：
```
'code-reviewer' (L34-56): shortDesc, detailedPrompt, tools: ['Read','Glob','Grep','Bash'], defaultModel: 'haiku'
'explorer' (L57-71): shortDesc, detailedPrompt, tools: ['Read','Glob','Grep','Bash'], defaultModel: 'haiku'  
'researcher' (L72-87): shortDesc, detailedPrompt, tools: ['Read','Glob','Grep','Bash','WebSearch','WebFetch'], defaultModel: 'haiku'
```

`buildBuiltinAgents()` 函数定义于 `agent-prompt-builder.ts` L116-130，遍历 `SUBAGENT_METADATA` 并转换为 SDK 的 `AgentDefinition` 格式。

SubAgent 通过 SDK agents 选项注册（`agent-orchestrator.ts` L1567-1569）：
```typescript
// 内置 SubAgent 定义（code-reviewer / explorer / researcher）
// SubAgent 模型最终由 CLAUDE_CODE_SUBAGENT_MODEL 兜底控制
```

### 3. Skill 是备选方案

Skill通过SDK Plugin系统加载（不通过System Prompt注入）：
- `plugins: [{ type: 'local', path: workspacePath }]`
- SDK自动发现 `skills/` 目录下的 SKILL.md
- Agent在对话中根据用户输入自动判断是否调用某个Skill

**证据**：插件加载配置于 `agent-orchestrator.ts` L1544：
```typescript
...(workspaceSlug && { plugins: [{ type: 'local' as const, path: getAgentWorkspacePath(workspaceSlug) }] }),
```

SDK 自动扫描 `{workspacePath}/skills/` 下的 SKILL.md。`agent-prompt-builder.ts` L331 的 System Prompt 中说明：
```
Skills 目录: ~/{configDirName}/agent-workspaces/{workspaceSlug}/skills/（Proma 只从此目录加载 skill）
```

内置12个Skill模板位于 `apps/electron/default-skills/`，通过 `seedDefaultSkills()`（`config-paths.ts` L467-516）同步到用户配置目录。

### 4. 权限模式可运行时切换

`updateSessionPermissionMode()` 已实现运行时动态切换 auto / bypassPermissions / plan。

**证据**：
- 函数定义：`agent-orchestrator.ts` L2179-2191
```typescript
async updateSessionPermissionMode(sessionId: string, mode: PromaPermissionMode): Promise<void> {
  if (!this.activeSessions.has(sessionId)) return
  this.sessionPermissionModes.set(sessionId, mode)
  this.eventBus.emit(sessionId, { kind: 'proma_event', event: { type: 'plan_mode_changed', sessionId, active: mode === 'plan', source: 'permission' } })
  if (this.adapter.setPermissionMode) {
    await this.adapter.setPermissionMode(sessionId, sdkPermissionModeForPromaMode(mode))
  }
}
```
- `sessionPermissionModes` Map 声明：`agent-orchestrator.ts` L518 `private sessionPermissionModes = new Map<string, PromaPermissionMode>()`
- SDK 侧实现：`claude-agent-adapter.ts` L907-913 `setPermissionMode()` 调用 SDK 的 `query.setPermissionMode()`
- 前端调用：`PermissionModeSelector.tsx` L71 `await window.electronAPI.updateSessionPermissionMode(sessionId, nextMode)`
- preload 桥接：`preload/index.ts` L570-571（类型定义）、L1611-1613（实现）

**`sessionPermissionModes` Map 的使用分布**：
| 行号 | 用途 |
|------|------|
| L518 | 声明 `Map<string, PromaPermissionMode>` |
| L1042 | 会话结束时 delete |
| L1289 | 初始化时 set 初始模式 |
| L1307 | 构建 canUseTool 闭包时 get |
| L1426 | 用户从 UI 选择模式后 set（运行时切换） |
| L2161 | 会话终止时清理 |
| L2181 | `updateSessionPermissionMode()` set |
| L2280 | 全部清理 clear |

### 5. 多模型支持现状

Proma已有统一的Provider适配层。

**证据**：`packages/core/src/providers/` 目录包含：
- `anthropic-adapter.ts` (491行) — Anthropic Claude API 适配
- `google-adapter.ts` (315行) — Google Gemini API 适配
- `openai-adapter.ts` (290行) — OpenAI API 适配
- `index.ts` (57行) — 统一导出
- `types.ts` (276行) — Provider 类型定义
- `thinking-capability.ts` (108行) — 思考能力抽象
- `sse-reader.ts` (378行) — SSE 流式读取

模型路由策略定义在 `agent-model-routing.ts` L23-33，`resolveAgentModelRouting()` 判断模型是否 DeepSeek 系列，以此决定 SubAgent 模型分配。

**但一个会话绑定单一模型**，运行时不可切换。`agent-orchestrator.ts` L932 `sendMessage()` 入参中 `modelId` 在构建 `queryOptions` 时确定（L1511 `model: modelId || DEFAULT_MODEL_ID`），会话运行期间不会变更。

多Provider设计主要是为了多渠道配置（用户在设置中选择渠道），不是为单会话内多模型并发设计。

## 对fork方案的影响

| PRD需求 | Proma现状 | 方案建议 |
|---------|----------|---------|
| 4个角色独立System Prompt | 不支持运行时切换（buildSystemPrompt 在 queryOptions 构建时固定，L1527-1539） | 方案1：每个角色开独立SubAgent会话；方案2：角色切换=新建SDK query() |
| 需求分析师+UI/UX顾问并行 | 不支持单会话多模型（sendMessage 单一 modelId，L1511） | 需要新增多Agent并发调度层 |
| 裁判Agent独立判定 | 可复用现有SubAgent模式（SUBAGENT_METADATA L33-88 + buildBuiltinAgents L116-130） | 注册为SubAgent，独立模型独立会话 |
