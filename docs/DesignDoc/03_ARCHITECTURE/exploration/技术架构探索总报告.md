## 三、关键架构决策

### 决策1：MVP串行角色切换，放弃并行

**结论**：需求分析师→UI/UX顾问→架构设计师→工程经理串行执行。

**理由**：
- Proma当前单会话单模型+并发守卫，无法直接支持多模型并发
- 串行切换改动量~9h，并行方案需~30h且涉及架构级变更
- 用户体感上只是"同一个人在不同阶段用不同方式帮你"
- PRD中"需求分析师+UI/UX顾问并行"的需求通过串行快速交替实现（同一会话内切换Prompt），对用户感知为两个角色同时在线

**实现方案**：Session Restart + Context Backfill
1. 当前阶段结束时，序列化上下文摘要
2. 创建新会话，加载目标角色的System Prompt和模型
3. 注入上下文摘要恢复对话连续性
4. 改动范围：~300行/8文件

**来源**：A2.1、B2

### 决策2：沙箱方案——文件系统工作区隔离为主

**结论**：L0文件系统工作区隔离 + L1子进程资源限制作为MVP方案。

**7方案对比结论**：

| 方案 | 适用性 | 判定 |
|------|--------|------|
| A. 文件系统工作区隔离 | ✅ 零安装门槛，全语言支持 | **主力方案** |
| B. WebContainer | ❌ 无Python支持 | 否决 |
| C. Docker | ❌ 零基础用户无法安装 | 否决 |
| D. iframe沙箱 | ❌ 能力完全不满足 | 否决 |
| E. 子进程资源限制 | ✅ 作为L1增强层 | **增强方案** |
| F. OS原生沙箱 | 远期L2加固 | Phase 3+ |
| G. CubeSandbox远程 | 最佳安全隔离 | Phase 3+远程部署 |

**安全策略**：
- 项目目录即沙箱边界——所有文件读写限定在project-root/
- 子进程cwd设为项目目录，环境变量沙箱化
- 网络白名单：仅放行npm registry、PyPI等必要域名
- L1层增加进程内存/CPU/时间限制

**来源**：A3.3、B3

### 决策3：点选纠错——data-ai-id标注为主

**结论**：Phase 1用data-ai-id标注方案；Phase 2加入截图+视觉模型兜底。

**4方案加权对比**（准确率×0.3 + 复杂度×0.2 + 生成影响×0.15 + 兼容性×0.15 + Agent理解×0.2）：

| 方案 | 综合评分 | 定位 |
|------|---------|------|
| A. data-ai-id标注 | 3.6 | Phase 1主路径 |
| D. 混合方案 | 3.6 | Phase 2完整形态 |
| B. DOM路径 | 3.2 | 否决 |
| C. 截图+视觉模型 | 3.6 | Phase 2兜底组件 |

**完整交互链路**：
1. 原型生成时为每个可交互元素注入data-ai-id和data-ai-type
2. 用户点击 → 事件委托捕获 → 读取data-ai-id → postMessage传递
3. 向导Agent接收ID + 上下文 → 生成修改规约JSON
4. 编程Agent根据规约修改代码 → 预览区刷新

**来源**：B4

## 四、Proma对接方案摘要

### 技术栈（基于Proma源码分析）

| 层级 | 技术 | 版本 |
|------|------|------|
| 桌面壳 | Electron | ^39.5.1 |
| UI框架 | React | ^18.3.1 |
| 语言 | TypeScript | ^5.0.0 |
| 构建 | Vite(渲染) + esbuild(主进程) | ^6.0.3 / ^0.24.0 |
| 状态管理 | Jotai | ^2.17.1 |
| 样式 | Tailwind CSS | ^3.4.17 |
| UI组件 | Radix UI | 14个包 |
| 图标 | Lucide React | ^0.460.0 |

### 扩展机制

Proma无插件系统。新增功能的唯一方式是代码级集成：
1. atoms/ 新增Jotai atom
2. components/ 新增React组件
3. TabContent.tsx 扩展TabType和渲染分支
4. MainArea.tsx 挂载Dialog

### 6页面挂载方案

| 页面 | 挂载方式 | 复杂度 |
|------|---------|--------|
| 模式选择页 | 替换现有Tab页或作为启动首页 | 低 |
| 快消型工作区 | 新增Tab类型 + 聊天/预览双区组件 | 中 |
| 长期迭代型工作区 | 新增Tab类型 + 聊天/文档/预览三区组件 | 中 |
| 我的项目 | 新增Tab类型 + 列表组件 | 低 |
| 设置页 | Dialog形式（复用SettingsDialog模式） | 低 |
| 分析看板 | 新增Tab类型 + 图表组件 | 中 |

预估改动量：~45-60文件，~3500-5000行新增代码。

### 文档体系挂载点

`workspace-files/` 目录是最佳项目文档挂载点。每个用户项目在此创建完整的文档目录树（01_PRD/→07_VERSIONS/）。
