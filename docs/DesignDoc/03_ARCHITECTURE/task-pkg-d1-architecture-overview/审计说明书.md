# 审计说明书：架构总览文档

> 适用任务：PKG-D1（architecture.md）
> 审计方法：四维并行审计 + 回归收敛（基于结构化文档多Agent终局验证方法论）

---

## 一、审计角色定义

### 审查员A：覆盖度审计

从以下来源逐条提取架构需求，对照 architecture.md 逐项标记覆盖状态：

| 需求来源 | 必须覆盖的内容 |
|---------|--------------|
| PRD §4 Agent架构 | 向导4角色、编程8角色、裁判Agent职责边界 |
| PRD §13 技术架构 | 7个关键模块、模型调度、文件系统通信 |
| 探索总报告 §三 关键决策 | 串行切换、沙箱L0+L1、点选纠错、技术选型、模型映射 |
| 探索 B1 | 6页面挂载方案、改动量预估 |
| 探索 B2 | Session Restart + Context Backfill 实现步骤 |
| 探索 B3 | L0+L1沙箱方案、否决方案及原因 |
| 探索 B4 | data-ai-id主路径方案 |
| 探索 C1/C2 | GLM 5.1/MiniMax验证结论 |
| UX sitemap | 6页面对应挂载方式 |

输出格式：`[A] 需求项 | 出处 | 覆盖状态(已覆盖/部分/遗漏) | 问题描述`

**通过标准**：覆盖率 ≥ 95%，无阻塞级遗漏。

### 审查员B：决策可追溯性审计

检查每个技术决策是否有探索报告数据支撑（非凭空断言）：

- L3 实测级：决策引用探索报告中的实测数据（如GLM端到端验证、MiniMax原型审查）
- L2 分析级：决策基于Proma源码分析
- L1 推理级：决策基于合理推演但无直接数据
- L0 无据级：纯断言

对9个章节中的所有决策逐条评级。**架构核心决策（技术选型、沙箱、角色切换、模型映射）必须达到L2或L3。**

输出格式：`[B] 决策摘要 | 当前等级 | 要求等级 | 差距描述`

**通过标准**：核心决策全部 ≥ L2，无非核心决策为L0。

### 审查员C：内部一致性审计

检查文档内部无自相矛盾：

| 检查项 | 方法 |
|--------|------|
| 模块依赖图 vs 模块划分表 | 图中有箭头的模块关系在表中是否对应 |
| 技术选型 vs Proma对接方案 | 选型是否与Proma现有技术栈一致 |
| 角色切换 vs 模型映射 | 切换顺序与每个阶段的模型是否对应 |
| 沙箱方案 vs 项目文档挂载 | 沙箱边界是否与文档目录结构一致 |
| 改动量预估 vs 模块划分 | 预估量是否覆盖所有新增模块 |

输出格式：`[C] 矛盾点 | 位置A | 位置B | 描述`

**通过标准**：零矛盾。

### 审查员D：PRD一致性审计

检查架构方案与PRD v0.2无矛盾：

- 所有PRD提及的关键模块是否在架构中实现
- 快消型/长期迭代型的架构差异是否有体现（隐于后台 vs 跳到前台）
- 裁判Agent独立模块是否保持独立性（未并入向导Agent）
- PlantUML约束层是否有对应实现

输出格式：`[D] 差异点 | PRD要求 | 架构实现 | 判定`

**通过标准**：零矛盾。

## 二、工作流程

### 第一轮：四维并行审计
同时启动A、B、C、D四个审查员，各自产出结构化问题清单。

### 汇总与分级
- **阻塞**：PRD核心技术需求遗漏 / 核心决策为L0无据 / 内部或PRD矛盾
- **严重**：覆盖率<95% / 非核心决策为L0 / 部分覆盖
- **建议**：可有更优表述、证据可更充分

### 修正
- 阻塞和严重问题：产出Agent修正
- 建议级：修正后标记"已优化"

### 回归审计
修正完成后，重新启动A、B、C、D简化版，只检查：
- 遗漏是否已补
- L0决策是否已有数据支撑
- 矛盾是否已消除

### 收敛判定
- 当前轮新发现阻塞+严重问题 = 0
- 覆盖率 ≥ 95%
- 核心决策全部 ≥ L2
- 零矛盾

若不收敛，重复修正+回归，最多3轮。超过3轮升级人类决策。

3. 遗留"待人类决策"项
