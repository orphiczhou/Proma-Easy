# 审计说明书：PlantUML 类图

> 适用任务：PKG-D2（class-diagram.puml）
> 审计方法：四维并行审计 + 回归收敛

---

## 一、审计角色定义

### 审查员A：域覆盖度审计

对照 architecture.md 模块划分，检查类图是否覆盖所有核心域：

| 域 | 至少应包含 |
|----|----------|
| 向导Agent引擎 | GuideAgent + 4角色类 |
| 编程Agent引擎 | CodingAgent + TestAgent + 至少1个可选角色 |
| 裁判Agent引擎 | JudgeAgent + 2个约束检查器 |
| 基础设施层 | SnapshotManager + TelemetryCollector + SandboxManager + ProjectDocumentSystem |

输出：`[A] 域/模块 | architecture.md出处 | 类图覆盖 | 缺失类`

**通过标准**：4域全覆盖，核心类 ≥ 15个，无关键类遗漏。

### 审查员B：PlantUML语法与规范审计

- `@startuml` / `@enduml` 配对
- 所有类、package、关系语法正确
- 关系线指向的类确实存在于图中
- package嵌套合法
- 无PlantUML语法错误

输出：`[B] 语法问题 | 位置 | 严重度 | 修复建议`

**通过标准**：零语法错误。

### 审查员C：architecture.md 一致性审计

逐项检查类图与 architecture.md 的一致性：

- architecture.md中的模块是否在类图中有对应package或类
- 类图中的类名是否与architecture.md中的模块/角色名一致
- 类间关系是否反映architecture.md中的模块依赖图

输出：`[C] 差异点 | architecture.md描述 | 类图实现 | 判定`

**通过标准**：零矛盾。

### 审查员D：PRD约束引用审计

检查类图是否反映PRD §8.4的PlantUML约束规范：
- 类属性类型是否明确标注
- 关系是否标注类型（继承/组合/依赖/关联）
- 是否为"机读格式"（非纯图片）
- 不包含面向用户的注释

输出：`[D] 约束项 | PRD要求 | 类图满足情况`

**通过标准**：所有PRD §8.4约束项满足。

---

## 二、工作流程

同PKG-D1：四维并行审计 → 汇总分级 → 修正 → 回归 → 收敛（最多3轮）。

### 分级标准
- **阻塞**：核心域缺失 / 语法不可解析 / 与architecture.md严重矛盾
- **严重**：核心类<15个 / 关系线错误 / 部分域覆盖不足
- **建议**：属性方法可更完整、注释可更清晰

### 收敛判定
- 阻塞+严重 = 0
- 4域全覆盖
- 零语法错误
- 与architecture.md零矛盾
