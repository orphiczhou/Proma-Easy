# 审计说明书：数据模型设计

> 适用任务：PKG-D4（data-model.md）
> 审计方法：四维并行审计 + 回归收敛

---

## 一、审计角色定义

### 审查员A：实体覆盖度审计

对照PRD和架构，检查5个实体是否覆盖所有持久化需求：

| 数据需求 | 来源 | 对应实体 |
|---------|------|---------|
| 项目基本信息 | PRD §3, architecture.md | Project |
| 版本快照 | PRD §7.4, A3报告 | Snapshot |
| 13个埋点事件 | PRD §12.4, US-R02 | TelemetryEvent |
| 会话恢复上下文 | B2报告, PRD §4.3 | SessionContext |
| 文档清单追踪 | PRD §5, §9 | DocumentMeta |

输出：`[A] 数据需求 | 出处 | 覆盖实体 | 状态`

**通过标准**：5个实体覆盖全部持久化需求，无遗漏。

### 审查员B：字段完整性与约束审计

逐实体检查：
- 每个字段含：名称、类型、必填、默认值、说明
- 主键已定义
- 外键关系已标注
- 枚举类型已列出所有合法值
- Snapshot不含分支字段（parentSnapshotId等）
- TelemetryEvent的eventType枚举完整列出13种

输出：`[B] 实体 | 问题字段 | 问题描述`

**通过标准**：5个实体字段完整，约束合理，Snapshot线性模型正确。

### 审查员C：架构一致性审计

- 存储方案与architecture.md一致（JSONL/文件系统，非关系型数据库）
- 快照存储路径与A3报告的fs.linkSync方案一致
- 会话上下文字段支持B2报告的Session Restart + Context Backfill
- DocumentMeta字段支持裁判Agent的硬约束检查流程

输出：`[C] 差异点 | architecture.md约定 | data-model实现`

**通过标准**：零矛盾。

### 审查员D：PRD一致性审计

- Snapshot模型符合PRD §7.4（线性回滚、自动触发）
- TelemetryEvent模型覆盖PRD §12.4全部13个事件
- 数据保留策略与PRD §12.2一致（30天/手动删除/脱敏）
- DocumentMeta支持PRD §5.2的7目录结构

输出：`[D] PRD要求 | data-model满足情况`

**通过标准**：全部PRD数据相关约束满足。

## 二、工作流程

同PKG-D1：四维并行 → 汇总分级 → 修正 → 回归 → 收敛。

### 分级标准
- **阻塞**：核心实体缺失 / 13事件清单不完整 / Snapshot含分支结构
- **严重**：字段定义不完整 / 外键缺失 / 与架构方案矛盾
- **建议**：JSON示例可更丰富、ER图可更清晰

### 收敛判定
- 阻塞+严重 = 0
- 5实体全覆盖
- 与architecture.md零矛盾
- 与PRD零矛盾
